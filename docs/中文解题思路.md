# 电动车购买预测：完整解题思路

## 1. 题目究竟要做什么

每一行是一位潜在消费者，特征包括年龄、收入、通勤距离、环境关注程度、补贴等信息。目标 `Will_Buy_EV` 是二分类，但提交的不是 Yes/No，而是“会购买”的概率。

比赛指标是 ROC-AUC。AUC 衡量正样本是否普遍排在负样本前面，因此重点是**排序质量**，不是把概率卡在 0.5 后的准确率。这也解释了为什么最终采用 rank blend（秩融合）：先把不同模型的预测转成相对名次，再加权平均，减少不同模型概率尺度不一致的影响。

## 2. 数据审查

本项目首先做了结构检查：

| 项目 | 结果 |
|---|---:|
| 训练集 | 668,665 行 |
| 测试集 | 286,571 行 |
| 正类比例 | 17.46% |
| 缺失值 | 0 |
| 重复 ID | 0 |
| test 与 sample_submission 的 ID 顺序 | 完全一致 |

正类比例不等于 50%，所以每折都使用 `StratifiedKFold`，让训练折和验证折的正类比例尽量一致。可比的特征消融固定为 5 折、随机种子 42；最强流水线随后增加两组 10 折和一组浅层 20 折版本，用不同划分与树形状降低测试预测方差。

还训练了一个“训练集 vs 测试集”的对抗验证模型。AUC 为 **0.50035**，接近随机猜测，说明没有发现明显的整体分布漂移。它不能证明每个细分人群都一致，但支持继续采用普通分层交叉验证。

## 3. 基线与逐步改进

项目没有直接堆最复杂模型，而是保留一条可解释的实验阶梯：

| 实验 | 核心变化 | OOF AUC |
|---|---|---:|
| CatBoost | 原生类别处理 | 0.941949 |
| LightGBM baseline | 清洗后的原始特征 | 0.942159 |
| Enhanced LightGBM | 增加全局频率编码 | 0.943221 |
| XGBoost digits | 增加数值位数结构 | 0.944006 |
| XGBoost + 简单 LOO TE | 简单留一目标编码，失败实验 | 0.901997 |
| Triple LightGBM | 数字位 + 频率 + 原始数据统计 + 三层平滑目标编码 | 0.946057 |
| Advanced LightGBM | 多尺度分箱、紧凑交叉键，单独使用未超过 Triple | 0.945971 |
| 10-fold Triple LightGBM | 每个子模型用 90% 训练数据 | 0.946184 |
| 另一种子 10-fold Triple | 改变外层折分，增加误差多样性 | 0.946155 |
| 浅层 20-fold Triple | 更浅的树 + 更高训练占比 | 0.946186 |
| 多视角重复 CV 秩融合 | 两个 10 折、浅层 20 折与三个辅助视角 | **0.946314** |

前几组特征实验使用同一套 5 折划分；10 折实验同时改变了训练比例和划分，因此它属于完整流水线比较，不能把全部增益归因于某一个特征。

## 4. 特征工程为什么有效

### 4.1 业务交互

环境关注程度是最强的单变量，单变量 AUC 为 **0.8435**；补贴可用性为 **0.7175**，年收入为 **0.6704**。高环境关注与补贴同时出现时，购买率明显更高。树模型能自动学习非线性交互，显式构造少量组合特征也能帮助模型更快发现这些关系。

这些结论只描述比赛的合成数据，不能直接说成真实世界因果关系。

### 4.2 频率编码

对某个取值 \(v\)，频率编码为：

\[
\operatorname{Freq}(v)=\frac{\#\{x_i=v\}}{N}.
\]

它告诉模型“这个值常不常见”。合成表格数据常在小数精度、重复模式或生成规则上留下痕迹，频率编码能捕捉这些结构。

### 4.3 数字位特征

收入、距离等连续数值被拆成整数位、小数位、取整或分箱特征。这不是通用业务规律，而是对 Playground 合成数据生成机制的合理假设。它在固定 OOF 验证中带来提升，才被保留。

### 4.4 目标编码与泄漏控制

普通目标编码用某个类别内的平均标签作为特征：

\[
TE(c)=\frac{\sum_{i:x_i=c}y_i+\alpha\mu}{n_c+\alpha},
\]

其中 \(\mu\) 是全局正类率，\(\alpha\) 控制平滑强度。类别样本越少，结果越靠近全局均值。

例如某类别有 10 行、其中 6 行购买，直接均值为 0.6；若全局正类率为 0.175、平滑强度为 10，编码变为 `(6 + 10×0.175)/(10+10) = 0.3875`。这相当于承认“10 行证据还不够强”，所以把结果拉回总体水平。

危险在于：如果一行自己的标签参与了自己的编码，验证分数会泄漏。本项目的处理方式是：

1. 先划分外层 5 折或 10 折；
2. 对外层训练部分再做内层交叉拟合，生成训练行编码；
3. 外层验证行和测试行只使用对应外层训练部分的统计；
4. 比较自动平滑、10、100 三种强度，让模型同时看到细粒度与稳定统计。

这就是“nested cross-fitted target encoding”。简单的 leave-one-out 版本反而降到 0.902，说明复杂特征必须靠验证决定去留，不能因为听起来高级就保留。

### 4.5 原始来源数据统计

比赛训练数据是扩充后的合成数据，公开的 10,000 行来源数据可用于构造目标均值查找特征。这里只把它当作外部统计信号；比赛验证标签仍严格隔离，避免把验证答案带入特征。

## 5. 模型与融合

LightGBM、XGBoost 和 CatBoost 都适合表格数据。最终最强的单模型是 Triple LightGBM。XGBoost 虽然单独略弱，但预测误差不完全相同，所以有融合价值。

对每个模型预测 \(p_m\) 先转成百分位秩 \(r_m\)，最终预测为：

\[
p_{blend}=0.25r_{LGBM20s}+0.1875r_{LGBM10b}+0.3375r_{LGBM10a}
+0.05625r_{LGBM5}+0.1125r_{Advanced}+0.05625r_{XGB}.
\]

注意：秩融合后的数值在 [0,1]，适合 AUC 排序提交，但没有经过概率校准。0.8 不能解释成“真实购买概率 80%”。若要用于业务决策，必须另外验证校准质量。

只搜索少量预先定义、容易解释的权重，避免在同一组 OOF 标签上做过密搜索。先把最强流水线从 5 折升级到 10 折，OOF 从 0.946057 提高到 **0.946184**；再加入另一个 10 折划分、浅层 20 折和辅助模型视角，最终 OOF 达到 **0.946314**，并在 5/5 个审计组超过最强单模型。Advanced LightGBM 自身略弱，但它提供互补排序，因此在融合中保留 11.25%。

## 6. 从本地验证到 Kaggle

提交前依次检查：

1. 列名严格为 `id`、`Will_Buy_EV`；
2. 恰好 286,571 行；
3. ID 唯一，并与 test、sample_submission 顺序完全一致；
4. 无缺失，概率全部在 [0,1]；
5. 保存 SHA-256，保证上传文件与审查文件是同一个。

自己的文件 `submission_best.csv` 的 SHA-256 是：

`616a1d0dedfb6c72b5dbd8cdda4926960cb9cbce0f6f3f4b1cd91d190545f82b`

第一版的本地 OOF 为 **0.946072**，Kaggle 公开榜为 **0.94627**。上一个已上传原创版本的 OOF 为 **0.946298**，公开榜为 **0.94640**。最终文件的 OOF 为 **0.946314**，与上面 SHA-256 匹配的 Kaggle 公开榜成绩为 **0.94641**。

同日榜单快照的 Top 10% 分界约为 **0.94650**。在 3,123 支队伍的快照中，0.94641 对应约第 502–525 的并列分数区间，约为前 16%–17%，因此这份原创模型**没有达到 Top 10%**。公开榜只使用约 20% 测试数据，最终私榜仍可能变化。

## 8. 研究生申请与面试怎么讲

建议按“问题—方法—证据—边界”来讲：

- 问题：大规模不平衡二分类，指标是排序型 AUC；
- 方法：固定分层 5 折、防泄漏目标编码、多个交叉验证变体、三个梯度提升模型与轻量秩融合；
- 证据：完整 ablation 表、失败实验、对抗验证、文件校验、Kaggle 公开成绩；
- 边界：合成数据不是因果研究，公开榜只作为最终外部验证。

可以强调的能力是：把一次竞赛做成了可复现的软件与研究记录，而不是只保留一个分数。GitHub 中包含模块化代码、测试、执行过的 Notebook、图表、实验日志、校验和、来源说明和诚实的负结果。

## 9. 怎样判断这些提升可信到什么程度

OOF 表示每一行的预测来自没有用这一行标签训练的模型。它是必要的防泄漏措施，但不等于一份完全没被看过的最终测试集：我们仍用同一批 OOF 标签选过特征和融合权重，所以最终数值可能有选择偏差。

这里的“5/5 审计折提升”，是把各模型的 OOF 预测按固定 5 组重新统计。它用于检查增益是否集中在少数行，不是 5 次独立的重复实验，也不是统计显著性证明。早停同样使用了验证折标签，微小增益需要独立折划分和 Kaggle 外部成绩共同检验。

本项目的原创增量在于完整可复现实现、多尺度与交叉特征、重复 10 折与浅层 20 折训练、验证比较和融合设计。梯度提升、目标编码和已有公开方法都有来源记录；“原创项目”不应被理解为发明全新的算法。面试时能解释这些选择及其局限，比声称算法从零发明更可信。

`reports/subgroup_metrics.csv` 进一步按城市、性别、补贴和收入分组检查排序质量。分组 AUC 低于总体 AUC 并不自动表示某组模型失效：总体指标包含组间比较，而分组指标只比较组内样本。例如补贴组间的购买率差异本身就贡献了总体排序。不能把分组差异直接解释为因果关系或公平性结论。

## 10. 建议你亲自练习的学习顺序

1. 先读 Notebook 的数据审查和单变量图，解释为什么使用 AUC 而不是 accuracy。
2. 在 `features.py` 中看一个频率编码例子，再运行 `tests/test_pipeline.py` 理解训练折与验证折的隔离。
3. 阅读 `triple.py` 的外层划分与内层 `TargetEncoder.fit_transform`，手画一行样本在每一步能看到哪些标签。
4. 阅读 `advanced.py`，挑出一个收入分箱和一个“关注程度×补贴”交叉键，解释它表达的假设。
5. 对照 `model_metrics.json` 看失败的 LOO 实验，练习用验证证据否定一个看似合理的方案。
6. 阅读 `ensemble.py`，计算一组秩融合权重，并解释为什么较弱的单模型仍可能提供互补信息。
7. 最后运行 `scripts/audit_predictions.py` 和提交校验工具，理解“模型训练成功”和“提交文件正确”是两项不同检查。

完整重跑入口为 `python scripts/reproduce.py`，需要先安装依赖并准备数据。它会重新训练全部记录的模型；只想阅读结果时无需重训，可直接打开 `reports/01_ev_purchase_project.html`。文件哈希用于确认这次交付的 CSV；换系统重训可能出现浮点细节差异，不应因此把一次合理复现判为失败。

## 11. 下一步可以自己做的扩展

1. 增加更多独立随机种子或保留一份完全未参与选型的验证集，检查 0.00001 级增益是否稳定；
2. 做分群误差分析，比较收入、年龄、补贴分组的 AUC；
3. 研究概率校准，但要注意校准未必提高 AUC；
4. 用 Optuna 做有预算上限的参数搜索，并保持嵌套验证；
5. 写一个 Model Card，记录适用范围、风险和复现环境。
